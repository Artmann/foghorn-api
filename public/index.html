Lighthouse for every page on your site.
Built for agents.

Foghorn reads your sitemap, audits every page for performance, accessibility, best practices and SEO, and groups what fails into a ranked list of issues. Your agent asks what to fix, fixes it, and checks again.

Get started → Connect an agent

The problem

Lighthouse checks one URL at a time. Your site has hundreds.

You run PageSpeed on the home page, it looks fine, and you move on. Meanwhile a blog template ships a 2 MB hero image, a product page loses its alt text, and a marketing page pulls in three tag managers. Nobody audits page 137 by hand.

Agents have the same blind spot. They can fix code, but they can't see how the site performs, so they can't tell what to fix first or whether a change helped.

Get started

There's no dashboard. You create an account and an API key with curl, and your agent does the rest.

  1. 01 Create an account

    curl -X POST https://foghorn-api.artgaard.workers.dev/auth/sign-up \
  -H "Content-Type: application/json" \
  -d '{"email": "you@example.com", "password": "a-long-password"}'

  2. 02 Sign in to get a token

    curl -X POST https://foghorn-api.artgaard.workers.dev/auth/sign-in \
  -H "Content-Type: application/json" \
  -d '{"email": "you@example.com", "password": "a-long-password"}'

    Returns a token that is valid for 24 hours.

  3. 03 Create an API key

    curl -X POST https://foghorn-api.artgaard.workers.dev/api-keys \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"name": "My agent"}'

    The key starts with fh_ and is shown once. Keep it somewhere safe.

  4. 04 Hand it to your agent

    Connect over MCP (see [04]) and say "Add www.example.com to Foghorn". It creates a team, adds the site, and the audits start.

What it does

  sitemap.xml ──▶  pages  ──▶  lighthouse  ──▶  issues
  ───────────      ─────       ──────────       ──────
  read & synced    ≤ 250       mobile, all      grouped by audit,
  every 4 hours    per site    4 categories     ranked by pages hit

  • Crawls the sitemap

    Add a domain and Foghorn reads its sitemap, including sitemap indexes. Pages that drop out of the sitemap are removed.

  • Audits every page

    Each page gets a full Lighthouse run through PageSpeed Insights: performance, accessibility, best practices and SEO.

  • Groups the failures

    Failing audits become issues, sorted by how many pages they hit, with the worst pages for each. Fix the template, not the page.

  • Keeps checking

    Sitemaps and pages are checked again every 4 hours, so the scores follow your deploys.

  • Shows what's pending

    Sites, pages and issues report pending, running, completed or failed, so an agent knows when to wait.

  • REST, OpenAPI, MCP

    The same data over a REST API with an OpenAPI spec, a remote MCP server, and an agent skill.

Connect your agent

Foghorn is a remote MCP server at https://foghorn-api.artgaard.workers.dev/mcp. Use your API key as a bearer token. 

claude mcp add --transport http foghorn \
  https://foghorn-api.artgaard.workers.dev/mcp \
  --header "Authorization: Bearer fh_..."
{
  "mcpServers": {
    "foghorn": {
      "type": "http",
      "url": "https://foghorn-api.artgaard.workers.dev/mcp",
      "headers": { "Authorization": "Bearer fh_..." }
    }
  }
}
npx skills add https://github.com/artmann/foghorn-api

For agents without MCP. The skill teaches them the REST API.

Things to ask

  • "Add www.example.com to Foghorn and tell me when it's done."
  • "Which accessibility issues affect the most pages?"
  • "Show me the five slowest pages and why they're slow."
  • "Fix the top SEO issue, then check the pages again."
  • "Is anything still pending on my site?"
